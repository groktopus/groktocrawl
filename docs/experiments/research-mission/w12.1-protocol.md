# W12.1 Research Mission frozen protocol

Status: **frozen before measurement**

## Arms

The control and treatment use the same pinned request, semantic case brief,
retrieval environment, source limits, model route, and renderer.

- **Control:** semantic case brief -> incumbent planning -> bounded acquisition
  -> synthesis.
- **Treatment:** the equivalent typed Research Mission -> obligation-aware
  planning -> the same bounded acquisition -> obligation-aware synthesis.

The typed object is the only intended intervention. It may constrain and account
for work but may not add facts, sources, or hidden reference answers.

## Intake comparison

For each case, the normalizer receives only the raw request and the public
Research Mission schema. It may either return a mission, ask a clarification, or
abstain. It does not receive the reference mission. Score required-field recall,
invented constraints, lost hard boundaries, unnecessary fields, clarification
utility, and correction burden.

## Corpus

Use 12 frozen cases, two from each stratum below:

| Stratum | Contract should do |
|---|---|
| Straightforward | Add little friction and preserve the direct request |
| Ambiguous | Expose a decision-changing ambiguity rather than guessing |
| Compound | Preserve every required subquestion and relationship |
| Temporal | Retain the as-of boundary and distinguish current from historical evidence |
| Contradictory source | Require conflict preservation and authority assessment |
| Unanswerable | Abstain with explicit missing evidence rather than manufacture closure |

Each case record contains a raw request, a neutral semantic case brief, a sealed
reference mission, weighted obligations, permitted scope, prohibited
assumptions, evidence roles, acceptable uncertainty, and the expected
clarification/abstention behavior. Reference records are authored before any arm
is executed and are never edited in place after measurement starts.

## Allocation

Use seed `20260919`. For each case, derive an arm order and rotate it between the
three repetitions so neither arm consistently runs first. Shuffle case order
within repetition. Preserve the generated work order and its hash. A failed
trial retains its allocation; retries append an attempt and never replace the
original record.

## Equivalence and leakage checks

Before admitting a paired result, an independent validator must establish:

1. both arms used the same case, source snapshot/corpus, budgets, model route,
   prompts outside the intervention, and renderer;
2. the control prose and typed mission encode the same obligations;
3. neither execution prompt contains reference grades or expected answers;
4. every acquired source and model call has a receipt;
5. every final claim links to evidence or is marked unresolved;
6. every clarification and manual correction is retained.

A failure of checks 1-3 invalidates the pair. Failures of checks 4-6 fail the
trial and remain in the failed-run ledger.

## Blinded evaluation

Seal arm names, run order, and internal mission representation. Randomize final
artifacts before grading. The grader receives the raw decision context,
independent obligation rubric, admitted evidence, and final artifact. It scores
each obligation and scope boundary with a retained rationale. Grade factual
support, coverage, and decision usefulness separately.

Adjudicate every schema failure, every hard-boundary finding, every disagreement
on a high-weight obligation, and a seeded 20% sample of the remaining pairs.
The grader uses `general`, but its receipts are distinct from production calls.
Changing the grader or prompt creates a new evaluation version and cannot
silently overwrite prior grades.

## Analysis

Report paired case-level effects and distributions by stratum and repetition.
Do not treat obligations from the same case as independent samples. Show raw
numerators and denominators beside percentages. Run these sensitivity checks:

- equal obligation weights;
- ambiguous grades counted as open;
- leave-one-case-out within each difficult stratum;
- failed trials counted once as worst-case and once as missing;
- adjudicated versus original model grades;
- latency and cost with and without clarification turns.

## Freeze and amendments

Before the first measured run, the freeze manifest must pin the exact source
commit, corpus, schema, runner, validator, prompts, analysis code, environment
identity, model route, and random work order. Preflight and smoke-test outputs
are stored outside the measured result tree. Any material correction produces a
visible amendment, a new freeze version, and a new result tree; invalid evidence
is retained rather than rewritten.

The immutable input and tooling hashes are recorded in
[`w12.1-freeze.json`](w12.1-freeze.json). Its `source_revision` identifies the
exact executable tree; the manifest itself is the later, reviewable declaration
that freezes that already-pushed revision. No measured call may use the manifest
commit as an implicit code upgrade.

### Visible v1 amendment

The first v1 measured launch exceeded the frozen failure guardrail after two of
its first 12 terminal trials failed. It is excluded in full. The retained
[research log](w12.1-research-log.md) records the failure, evidence-tree digest,
and bounded transport/output correction. A separate v2 freeze must be published
before another measured call; this v1 manifest and launch remain immutable.

The corrected executable and analysis tree is pinned by
[`w12.1-freeze-v2.json`](w12.1-freeze-v2.json). V2 may start only after one
excluded control and one excluded treatment trial both pass exact output,
envelope retention, response-digest, and private-permission checks.

### Visible v2 amendment

The v2 matched preflight passed, but the v2 measured launch was stopped after
three completed downstream trials. A pre-execution audit found that the pinned
analysis program did not yet emit every sensitivity analysis promised above.
The partial launch is excluded in full; it is retained and hashed in the
[research log](w12.1-research-log.md).

V3 adds an independent automated regrade lane. It regrades every candidate with
a hard-boundary finding or non-closed obligation weighted four or five, then a
seeded 20% sample of the remaining candidates. This is an evaluator-disagreement
sensitivity check, not human adjudication and not a replacement for the primary
blind grade. Schema-invalid calls remain failed-run evidence and are never sent
to a grader as if they were valid candidates. V3 also makes all six sensitivity
outputs machine-readable and raises the maximum measured-call ceiling to 288:
216 primary calls plus at most 72 independent regrades.

### Visible v3 amendment

The v3 launch was stopped after 23 terminal downstream trials: 22 completed and
one failed. That failure was below the frozen 10% operational guardrail, but it
revealed that the validator still required every allocation to succeed and the
grader required all 72 candidates. This contradicted the frozen failed-trial
sensitivity rule. The partial launch is excluded in full and retained in the
research log.

V4 treats a terminal failed allocation as valid failed-run evidence while still
enforcing the 10% lane guardrail. Only completed candidates proceed to grading.
The missing-data view uses complete graded observations; the conservative view
assigns a missing treatment zero coverage, one scope violation, usefulness zero,
and a hard-boundary failure, while assigning a missing control full coverage,
no scope violation, and usefulness 100. This rule is deliberately unfavorable
to the treatment and is frozen before v4 measurement.

### Visible v4 amendment

All 72 v4 downstream trials completed, but the intake lane crossed the 10%
guardrail after 14 terminal calls: 11 completed and three failed. Two responses
exhausted the completion budget without returning content; one returned a valid
JSON object followed by extra text. The intake runner had supplied the schema in
the prompt but had not used the provider's structured-output contract. The full
v4 launch is excluded and retained in the research log.

V5 supplies the same public `IntakeResult` schema to the provider for strict
output validation. This changes only the common intake transport envelope; it
does not change the cases, semantic instructions, reference missions, scoring,
or downstream control/treatment intervention.

### Visible v5 amendment

V5 closed 71 of 72 downstream trials, with one failure inside the guardrail.
The intake schema preflight passed, but the measured intake lane was stopped
after nine terminal calls: seven completed and two exhausted all 10,000 tokens
as hidden reasoning without returning content. Strict output validation solved
the malformed-envelope failure but did not bound model deliberation. The full
v5 launch is excluded and retained in the research log.

V6 uses `reasoning_effort=minimal` for intake normalization only. Downstream
generation and all grading remain at `low`. The intake task, schema, token
ceiling, cases, and scoring remain unchanged. V6 requires excluded preflights on
the two difficult cases that exhausted the v5 budget before measurement starts.

### Visible v6 amendment

The fresh control, treatment, and hostile-source intake preflights passed. The
recovery/portability intake case still exhausted 10,000 tokens: 8,828 were
reported as reasoning tokens, leaving insufficient room for the required
mission object. V6 did not enter measurement.

V7 retains minimal intake reasoning and raises only the intake completion ceiling
to 20,000 tokens. Downstream generation and every grading lane remain capped at
10,000. The failed recovery/portability case must pass an excluded preflight
before v7 measurement begins.

### Visible v7 amendment

V7 kept downstream and intake failures within their lane guardrails, then the
blind downstream grader crossed its guardrail after 12 terminal calls: ten
completed and two exhausted the 10,000-token budget as hidden reasoning without
returning grades. The full v7 launch is excluded and retained in the research
log.

V8 uses minimal reasoning and a 20,000-token ceiling for all evaluator calls:
downstream grading, intake grading, and independent regrading. Production-like
downstream generation remains at low reasoning and 10,000 tokens; intake remains
at minimal reasoning and 20,000 tokens. The rubric, blinding, selection, and
decision gates do not change. Both failed grade candidates must pass excluded
preflights before v8 measurement.

### Visible v8 evaluation amendment

All four primary v8 lanes closed within their guardrails. The independent
regrade launcher then failed before writing a work order or making a model call
because it referenced the canonical-digest helper from the wrong Python module.
This defect cannot affect the already-recorded downstream, intake, or blind
grade content.

V9 fixes and directly tests that digest call. Its result tree inherits an exact,
read-only copy of the hashed v8 primary evidence and appends only v9 independent
regrades, validation, and analysis. The inherited tree digest and file count are
recorded before copying. Any mismatch invalidates v9; no primary record may be
rewritten or regenerated inside the inherited tree.

### Visible v9 pre-execution amendment

A dry-run audit found that the validator accepted only one source revision for
all lanes. An inherited packet needs two explicit revisions: v8 for the copied
primary manifests and v10 for newly appended regrades. V9 made no model calls.
V10 adds the separate inherited-primary revision argument; every lane must still
match its declared revision exactly.

### Visible v10 amendment

V10 selected 20 independent regrades and stopped after 17 terminal calls when
three schema-shape failures raised the lane rate to 17.65%. Two responses wrapped
the grade in an extra object; one omitted the final boundary fields. All three
finished normally and stayed inside the expanded token budget. V10 is excluded
as an evaluation result; its inherited primary packet remains unchanged.

V11 adds an exact top-level field list and explicitly forbids wrapper objects in
the independent-regrade prompt. The schema, rubric, candidate content, selection
rule, and primary evidence do not change. V11 again starts from an exact copy of
the hashed v8 primary tree and reruns the full deterministic 20-item regrade
selection.
